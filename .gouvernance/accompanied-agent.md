# Agent rights: accompanied development
The agent writes all application code and tests, installs declared project development dependencies, creates work branches, stages, commits and pushes work branches, and opens or updates pull requests for the authorized task. Do not ask repeatedly for these routine steps.
The human reviews, critiques and merges. No direct push to main/master, no tags or releases, no force push, no hook bypass, no destructive reset/clean, no privilege escalation and no credential access.
Protected paths are readable for context but not directly writable: .git/, .github/, .githooks/, .gouvernance/, .GCC/PROTOCOL.md, AGENTS.md, CLAUDE.md, .codex/, .claude/, .agents/, .coding-stuff/, scripts/setup_workspace.py, scripts/quality_gate.py, scripts/start_codex.py, scripts/apply_antigravity_permissions.py and the harness installation/configuration directories outside this repository.
Only standard Git commands may update Git metadata for work branches. Never manually edit .git/config, hooks, objects, refs, credential files or installed harness binaries. Guardrail changes require a specific maintainer request; the initial workspace configuration is such a request.
Secrets remain unreadable and unwritable; .env.example contains examples only.
Filesystem sandboxes apply to subprocesses too: making all of .git read-only also prevents git add/commit. The Codex profile therefore permits Git metadata writes, with direct manipulation forbidden by instructions, command rules, hooks and server controls where enabled. This is not a claim of per-process filesystem isolation.
